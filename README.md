# Техническое задание на разработку программного продукта для планирования встреч
## Команда: We Tried

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.

# US&UC. Задачи Frontend
## User Stories
1. Я, как новый сотрудник, хочу зарегистрироваться, чтобы получить доступ к корпоративному календарю.

2. Я, как зарегистрированный пользователь, хочу авторизоваться, чтобы получить доступ к календарю встреч.

3. Я, как пользователь, хочу редактировать свои ФИО и должность, чтобы коллеги видели актуальную информацию обо мне.

4. Я, как организатор, хочу создать встречу на конкретный час и пригласить коллег, чтобы забронировать их время.

5. Я, как приглашенный, хочу видеть список заявок и давать бинарный ответ (принял/отклонил), чтобы планировать свой день.

6. Я, как активный сотрудник, хочу получать список своих подтвержденных встреч за период, чтобы видеть свою загрузку.

7. Я, как организатор, хочу иметь возможность выбирать сотрудников, приглашаемых на встречу. 

## Use Cases
UC-01: Регистрация и аутентификация

* Цель: Обеспечить безопасный доступ к API. 
* Основной поток: клиент отправляет POST /api/auth/register с данными пользователя. 
* Бэкенд проверяет валидность email и хэширует пароль.
* Для всех защищенных эндпоинтов используется HTTP Basic Auth. 
* Бэкенд извлекает учетные данные из заголовка Authorization.

* Альтернативный поток: Пользователь ввёл некорректный email/пароль. 
* Пользователь не зарегистрирован.
* Ошибки от сервера. 

UC-02: Редактирование данных пользователя 

* Цель: Редактирование данных для поддержания их актуальности.
* Предусловия: пользователь зарегистрирован. 
* Основной поток: проверка, является ли пользователь тем лицом, которое владеет этим профилем. 
* Клиент отправляет запрос на изменение данных и данные на сервер. 
* Бекенд обрабатывает запрос, бекенд возвращает статус запроса. 

* Альтернативный поток:
* Пользователь не прошёл проверку. 
* Ошибка от сервера. 

UC-03: Создание встречи с валидацией слотов

* Цель: Создать событие в календаре. 
* Предусловия: Организатор авторизован. 
* Основной поток: организатор передает название, дату, час начала и список ID участников.
* Бизнес-правило: Бэкенд проверяет, что время начала имеет вид HH:00:00 (минуты и секунды строго нулевые).
* Создается запись в meetings и записи в invitations (статус PENDING) для всех участников.

* Альтернативный поток: Время указано некорректно. 
* Ошибка от сервера. 

UC-04: Обработка приглашения

* Цель: Изменение статуса участия. 
* Основной поток: Участник запрашивает список своих PENDING приглашений.
* Участник отправляет PATCH запрос с новым статусом (ACCEPTED / DECLINED).
* Бэкенд проверяет, что этот invitationId принадлежит именно этому пользователю.

* Альтернативный поток: Ошибка от сервера.
